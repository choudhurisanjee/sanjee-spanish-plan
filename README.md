# Español — study tracker

A mobile web app for one person's 15-week Spanish plan, Sep 14 – Dec 27 2026.
No build step, no framework, no dependencies. Open `index.html` and it runs.

---

## Files

| File | What it owns |
|---|---|
| `plan.js` | **The plan.** Phases, budgets, milestones, resources. The only file you hand-edit. |
| `app.js` | Everything else: dates, storage, materialisation, the three screens, the sheet. |
| `sync.js` | Mirrors state to a secret GitHub gist. Self-contained; delete it and the app still works locally. |
| `styles.css` | The whole look. ~380 lines, one accent colour, no webfont. |
| `index.html` | Shell and iOS meta tags. Rarely needs touching. |
| `sw.js` | Offline cache. **Bump `CACHE` on every deploy** or the phone keeps serving old files. |
| `manifest.json` | Home-screen install. |
| `icons/` | Generated by `tools/make-icons.py`. Re-run it if you change the palette. |
| `notes/` | The original build specs and the design pitch. Not part of the app. |

## The two kinds of data

**The plan** is static, lives in `plan.js`, and is safe to rewrite at any time.

**Week records** live in `localStorage`, keyed by the ISO date of that week's
Monday (`spanish:week:2026-09-14`). A week is built from its phase's `budget`
the first time you open it, and is **never regenerated** after that. Editing
`plan.js` cannot damage a week you've already started.

That has one consequence worth knowing: if you change a phase's `budget` or its
`days`, weeks you've already opened keep the old ones. To pull a not-yet-started
week onto the new layout, open it and press **Reset to plan** at the bottom.

## Editing `plan.js`

**Change a weekly budget.** Edit the `budget` array on a phase. `count` is
sessions per week, `targetMinutes` is each session's length. For a type marked
`daily: true`, `count` means *days per week* instead.

**Change which days things land on.** `days` on a budget entry is the default
weekly layout, so a new week arrives already scheduled and you only move what
differs from the norm. `0` is Monday through `6` for Sunday, one entry per
session:

```js
{ type: "textbook", count: 3, targetMinutes: 45, days: [0, 2, 5] }  // Mon, Wed, Sat
```

Fewer days than `count` leaves the remainder in the tray, which is useful for
"three fixed sessions and one wherever it fits". Drop `days` entirely and
everything starts unscheduled. Daily types ignore it — they already cover the
whole week.

**Add a phase.** Copy a phase block, give it a new `id` (`"p5"` — ids are
permanent; renumbering existing ones orphans the weeks that recorded them),
list its `weeks`, and raise `weekCount` to match.

**Add a milestone.** Append to `milestones` with a fresh `id`. It shows up
inline in that week and in the Progress list. Never reuse an old `id` — a
checked milestone is stored by id.

**Add an activity type.** Add a key to `activityTypes` with `label`, a
two-letter `code`, a `color` / `colorDark` pair, and `resources`. Then
reference it from a phase `budget`. The colour flows through automatically —
the code, each row's left rule, the glance strip and the progress bar all read
it, so there's no CSS to touch.
A type with no budget anywhere is fine — it just won't appear until you add a
session of it by hand. (`mock` is set up that way on purpose: the mock exams
are milestones, not weekly sessions.)

**Move the start date.** Weeks are keyed by date, so changing `startDate`
orphans existing records rather than corrupting them. They still render and
still count, labelled "Off-plan". Export first if you care about them.

## Running it locally

```sh
python3 -m http.server 8000
```

Then `http://localhost:8000`. To open it on the phone, use your machine's LAN
address (`http://192.168.x.x:8000`) with both devices on the same Wi-Fi.

Opening `index.html` directly from disk also works. The service worker doesn't
register over `file://`, so there's no offline caching that way — everything
else behaves normally.

## Deploying to GitHub Pages

```sh
git init
git add .
git commit -m "Español study tracker"
git branch -M main
git remote add origin git@github.com:<you>/<repo>.git
git push -u origin main
```

Then **Settings → Pages → Source: Deploy from a branch → main → / (root)**.

On every later deploy, bump `CACHE` in `sw.js` (`espanol-v1` → `espanol-v2`)
before pushing. Without it the phone serves the cached copy and your `plan.js`
edits won't appear.

> Free GitHub accounts can only serve Pages from a **public** repo, so your
> study plan would be publicly readable. It's a Spanish study plan, so that's
> probably fine — but if it isn't, a private repo with Pages needs GitHub Pro.

## Install it on the phone — do this first

Open the Pages URL in Safari, then **Share → Add to Home Screen**.

This isn't decoration. iOS clears localStorage for ordinary websites after
7 days of no interaction; home-screen web apps are exempt from that sweep.
It also means the installed app has **its own storage, separate from Safari's** —
anything you log in Safari won't appear in the installed app. So install first,
then start logging.

## Backup

Set it up on day one: **Progress → Backup & sync**.

1. Make a fine-grained token at github.com/settings/tokens with gist access.
2. Paste it in, press **Create gist**. The id fills itself in.

After that every change pushes to a secret gist about two seconds later, and
the app pulls on launch. The dot in the header shows the state — filled means
synced, hollow means it couldn't reach GitHub.

Secret gist means *unlisted*, not private: anyone with the URL can read it.

The alternative is manual: **Download** writes a `.json` into Files. Progress
nags you about this only if you have no sync configured and haven't exported in
two weeks.

Nothing you export ever contains the GitHub token.

## Things worth knowing

- **Minutes are the signal.** Tapping the `[ ]` on a row marks it done at its
  target minutes in one tap. Tap the row body instead to open the sheet and set
  the real number.
- **A note replaces the label.** Four rows all reading "Listening" become
  useful once you write what they actually were.
- **Progress counts elapsed weeks, not opened ones.** Browsing ahead to week 12
  doesn't add its hours to your denominator.
- **Unfinished work doesn't roll over.** A week ends and whatever's left stays
  in that week. There's no debt ledger, and nothing renders in red.
- **One level of undo** is kept before any import or any sync that replaces
  local state. Both are restorable from the Data screen.

## Schema changes

Every record carries `schemaVersion`. If you reshape a week record, bump
`PLAN.schemaVersion` and fill in the `v === 1` case in `migrate()` in `app.js`.
Migrations run on read and write back once, so each record is converted exactly
once.
